# PP 파이프라인 시나리오 검사 — 2026-10-30

**수정 후 실API 시나리오 98/98, 수치 조합 10,000/10,000을 통과했습니다.**

실제 FastAPI를 별도 로컬 포트로 실행하고 HTTP로 호출했습니다. PostgreSQL은 새 검증용 스키마,
Neo4j·법령 RAG는 현재 자료를 실제 조회했습니다. 검사가 끝나면 검증용 프로세스·스키마만 정리했고,
기존 실행 서버와 사용자 안건은 수정하지 않았습니다. 남아 있는 `pp_stress_*` 스키마는 0개였습니다.

**공장 물량·오염률·공정 성능·가격은 합성 값입니다.** 실제 기업의 추천 정답률이나 현장 수율을 검증한 것은 아닙니다.
사용자 제공 성적서 이미지 3장은 실제 원본으로 별도 검사했습니다. 유료 GPT·Azure OCR·지도 호출은 실행하지 않았습니다.

## 재현

Docker PostgreSQL·Neo4j와 로컬 설정이 준비된 환경에서 실행합니다. 실행기는 새 테스트 스키마와 자기 자식 프로세스만 정리합니다.

```powershell
.\.venv\Scripts\python.exe scripts/run_pp_stress.py --numeric-cases 10000 --kg --output data/local/pp-stress-rerun.json
```

사용자 문서 검사는 원본을 보유한 PC에서 `--document <절대경로>`를 추가합니다. 기본 재현 명령은 개인 파일을 요구하지 않습니다.
그 경우 원본 검사 3개가 빠진 **95개** 사례를 실행합니다.

```powershell
$env:RUN_POSTGRES_INTEGRATION='true'
$env:RUN_NEO4J_INTEGRATION='true'
.\.venv\Scripts\python.exe -m pytest -q
```
