# 내 사업장에서 공정별 시설 조사하기

`POST /analysis/site-discovery`에 **서버가 확인한 출발 사업장 정보와 폐자원 로트**를 전달하면,
현재 KG 경로와 각 공정의 시설 명부 조사 대상을 함께 받습니다.
주소·회사 이름을 LLM이 추정하거나, 기존 공정 경로의 시설을 가까운 업체로 자동 바꾸지는 않습니다.

## 무엇이 새로 연결됐나

**출발 사업장 → KG의 공정 경로 → 공정별 시설 명부 조회 → 직선거리순 조사 목록**입니다.

- 반복되는 공정은 한 번 조회하고, 해당하는 모든 후보·단계 ID를 연결합니다.
- 같은 KG·명부·코드표 세대를 확인하고, 중간에 바뀌면 결과를 섞지 않고 실패시킵니다.
- 시설 명부의 전체 매칭 결과를 거리순으로 정렬한 뒤 페이지를 자릅니다. 받은 한 페이지만 재정렬해 최근접이라고 부르지 않습니다.
- 좌표 없는 시설은 뒤에 남기며, 조회 한도에 걸리면 미수집 건수와 커서를 표시합니다.
- 사업장 ID·수거 주소/좌표가 바뀌면 `context_sha256`도 달라집니다.

## 요청 예시

아래 기업·사업장·좌표는 **가상 입력**입니다. 실제 SK 공장을 식별·인증했다는 예시가 아닙니다.
Re_server는 회원이 해당 사업장에 접근 가능한지와 수거 지점의 주소·좌표를 확인한 뒤 전달해야 합니다.
현재 AI 서비스의 응답은 `origin_basis=server_supplied_not_independently_verified`로 이 경계를 표시합니다.

```json
{
  "origin": {
    "organisation_id": "synthetic-org",
    "site_id": "synthetic-site",
    "label": "가상 발생 사업장",
    "pickup_address": "시연용 가상 수거 위치",
    "latitude": 37.2,
    "longitude": 127.0,
    "country": "KR"
  },
  "lot": {
    "material": "PP",
    "input_form": "scrap",
    "quantity_kg": 3000,
    "color": "검정"
  },
  "max_plan_pages": 20,
  "facility_page_size": 25,
  "max_facility_pages": 2
}
```

이번 계약은 국내 사업장 좌표를 대상으로 합니다. 좌표를 바꾸어 넣거나, 중간 KG 커서로 시작하거나,
생성 모델 옵션·견적·임의 원본 경로를 넣으면 입력 검증에서 거절합니다.

## 결과 읽기

| 필드 | 의미 |
| --- | --- |
| `origin`, `context_sha256` | 전달한 출발지와 조회 맥락 해시. 사업장 권한 확인이나 견적 바인딩을 증명하는 서명은 아님 |
| `candidates` | 원래 KG의 경로·시설 공개 조건. 명부 업체로 자동 치환하지 않음 |
| `facility_searches[].candidate_stage_refs` | 이 공정 조사가 필요한 후보·단계 ID |
| `reference_bindings` | KG의 공개 공정 근거·역할 가설. 명부 검색 결과와 별도 |
| `registry_candidates` | 명부에서 찾아 가까운 순으로 정리한 조사 대상 |
| `material_match`, `equipment_mentions` | 소재 이름·넓은 코드·미해석 코드·설비 단어 중 어떤 단서로 찾았는지 |
| `straight_line_distance_km` | 배출 사업장→해당 명부 좌표의 직선거리 |
| `stage_capability`, 허가·인수 관련 필드 | 실제 공정 수행·허가·해당 로트 인수는 여전히 미확인 |
| `coverage`와 공정별 `next_cursor` | 수집 건수·전체 매칭 건수·불완전 조회 범위 |

`road_distance_km`·`transport_cost_krw`는 아직 `null`입니다.
후속 공정의 거리도 **출발 사업장에 대한 근접성 조사**이며, 앞 처리시설에서 다음 시설까지 운송하는 거리로 사용하면 안 됩니다.
주소가 없는 후보·넓은 폐합성수지 분류·미해석 코드도 남기므로, 가까운 순서가 처리 적합성·가격 순위는 아닙니다.

커서는 해당 공정의 기존 `/kg/facility-candidates` 계약으로 이어서 조회할 수 있습니다.
같은 좌표·공정·정렬 조건을 유지해야 하며 변경하면 기존 커서를 재사용할 수 없습니다.
새 통합 사업장 요청 자체는 첫 KG 페이지부터 다시 시작합니다.

## 기존 API와의 관계

기존 `/analysis/research`, `/analysis/review`, `/analysis/kg-lci`를 대체하지 않습니다.
사업장 조사는 검색 모델·법규 Auditor·가격·LCI 계산을 호출하지 않으며, 등록 KG가 지원하지 않는 소재를 새로 만들어 넣지 않습니다.
`/analysis/kg-lci`는 별도 PR #30의 기능이며 해당 PR 반영 여부와 별개로 이 API는 실행됩니다.
시설 조사 결과를 기존 수치 비교에 바로 주입하는 기능도 없습니다.

따라서 반환 상태는 `REVIEW`, 최종 추천 목록은 비어 있고 `dispatch_approved=false`입니다.
다음 단계는 **사업장 권한/UI 연동 → 시설별 실제 공정·허가·인수 확인 → 도로 경로와 같은 로트 견적 → 전체 비용·탄소·Critic 연결**입니다.

## 실제 DB 확인

[실행 기록](evaluation/site-discovery-2026-10-24.json): 가상 출발 좌표·PP 3톤을 실제 활성 KG·전국 명부로 조회했습니다.
공정 경로 3개와 서로 다른 공정 4개를 연결했고 명부는 9,604개 등록 레코드였습니다.
각 공정의 매칭 결과는 2,355개이며 시연 한도상 첫 3개만 받았습니다. 수집 범위는 부분 조회로 표시했습니다.
직선거리 0.6·0.8·0.9km인 같은 가까운 레코드가 네 공정에 모두 나타났으며,
이 중 미해석 코드 단서도 포함됐습니다. 이는 **시설별 설비·투입 규격 데이터가 아직 부족하다는 실제 한계**입니다.
각 업체가 네 공정을 모두 수행한다거나 PP를 받을 수 있다고 판정하지 않았습니다.

원래 명부의 업체명·주소 등 본문은 Git과 외부 모델 전송에서 계속 제외했습니다.
Git의 기록에는 등록 ID·거리·단서 종류·기준일·조회 해시와 범위만 남겼고 내부 원시 응답은 로컬에 보관했습니다.
