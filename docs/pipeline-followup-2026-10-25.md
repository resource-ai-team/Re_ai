# 추가 보강: 기본 조문 누락과 지도 표시

이 문서는 [앞선 검증](pipeline-validation-2026-10-25.md) 이후의 추가 작업입니다.
동료의 [PR #49](https://github.com/resource-ai-team/Re_ai/pull/49)를 반영한 develop `9120006`을 기준으로 합니다.

## 이번에 달라진 것

**벡터 검색 + 단계별 기본 조문 직접 조회**를 함께 실행합니다.

기존 법령 검색은 허가 업종 질문에서 핵심 제25조를 놓쳤습니다. 그래서 공정 검토에 필요한
조사 출발 조문까지 Top K 검색 결과에만 의존하지 않도록 했습니다.
일반 RAG의 검색 정확도가 올라갔다고 주장하는 변경은 아닙니다.

| 단계 | 직접 조회할 조사 출발점 |
| --- | --- |
| 분류 | 폐기물관리법 제2조 |
| 공정 | 제13조·제13조의2·제13조의3 |
| 시설 | 제25조·제29조·제46조 |
| 위탁·인계 | 제17조·제18조·제19조 |

이 10개는 **모든 사례에 적용되는 의무 목록이 아닙니다.** 허가·신고·자체 처리의 조건과
예외·위임 규정을 검토하기 위한 출발점입니다. 예를 들어 시설 관련 자료에 제25조뿐 아니라
시설 설치·처리 신고도 함께 남겨, 모든 경로에 같은 허가를 요구한다고 해석하지 않게 했습니다.
실제 법규 적용성·현행 허가·로트 인수는 계속 별도로 확인해야 합니다.

출처는 수집한 [국가법령정보센터 폐기물관리법](https://www.law.go.kr/법령/폐기물관리법) 원문입니다.
설정은 패키지의 `rag/resources/legal-baselines.json`에서 버전 관리합니다. 법률 전문가 검수는 별도입니다.

## 원문을 어떻게 연결하나요?

1. 서버가 정한 법령 ID·정확한 조문 ID를 사용해 **PostgreSQL의 공개 LAW 자료만** 한 SQL 시점에서 조회합니다.
2. 현재 활성·시행일 조건을 적용합니다. 기업별 자료는 읽지 않습니다. 제25조의3을 제25조 대신 가져오지 않습니다.
3. 법명·조문 제목·인용 위치·현재 버전 중복·조각 누락을 검사합니다.
4. 문서 버전·시행일·수집일·원래 인용·본문 해시를 보존하고 공정/인계 ID에 연결합니다.
5. 원문을 확보해도 `applicability=not_audited`입니다. 미확보·부분 조회·제목 변경은 확인 필요로 남깁니다.
   확인된 조문 연결 오류·현재 버전 중복은 `REVISE`와 검증 단계 재검토를 요청합니다.
6. 같은 조사 안에서 벡터 검색과 직접 조회가 서로 다른 버전의 같은 법령을 반환하면 `REVISE`로 다시 조회를 요청합니다.

`complete=true`는 **현재 인덱스에 들어 있는 해당 조문 조각을 빠짐없이 가져왔다**는 뜻입니다.
공식 원문 전체 수집의 독립 검수, 실시간 법령 변경 확인, 예외·적용성·적법성 검증을 뜻하지 않습니다.
본문 해시는 로컬 내용 대조용이며 공식 전자서명은 아닙니다.

조회는 로컬 DB만 이용합니다. 새로운 유료 모델·지도 호출이나 외부 기업 정보 전송은 없습니다.
로컬 자료 교체·장애·없는 조문·현재 버전 충돌을 통과로 바꾸지 않습니다.
조문 목록을 수정하면 서버를 재시작해야 합니다. 실제 법령 조각은 매 요청마다 DB에서 새로 조회합니다.

## 팀이 사용할 응답 필드

- `research.legal_baselines`: 중복 없이 수집한 10개 출발 조문과 출처·검사 상태.
- `candidate.legal_baseline_tasks`: 이 공정/인계 단계가 확인할 주제와 `reference_ids`.
- `coverage.legal_baseline_retrieval_complete`: 출발 조문 조회 완료 여부.
- `coverage.legal_baseline_applicability_audited`: 현재 항상 false.
- `critic`: 근거 미완료·적용성 미검수·확인된 연결 오류와 다음 행동.

벡터 검색 한도가 1회여도 기본 조문은 별도로 조회합니다. 이 조회는 서버 소유의 작은 목록으로 제한되며,
프롬프트가 임의 SQL이나 서버 파일 경로를 지정할 수 없습니다. 기본 목록이 전체 관련 법령을 포괄하지는 않습니다.

## 지도는 한 지점에 배지 하나

기존 `map_markers`는 모든 세부 확인 사항을 보존합니다. 새 `map_marker_groups`는
같은 후보·공정/운송 구간의 항목을 묶어 화면에 배지 하나로 표시하기 위한 필드입니다.

| 필드 | 화면에서 쓰는 방법 |
| --- | --- |
| `group_id`, `target_id` | 같은 지도 지점의 배지를 갱신 |
| `issue_count` | 배지에 확인할 항목 수 표시 |
| `error_count` | 확인된 입력·연결·계산 오류 수 |
| `confirmation_count` | 원문·조건·자료를 더 확인해야 하는 항목 수 |
| `marker_ids`, `evidence_ids` | 클릭하면 기존 세부 항목과 근거 펼치기 |

이는 실제 사고가 확인됐다는 표시가 아닙니다. 전역 오류는 지도에 억지로 붙이지 않고 기존 critic 목록에 남습니다.
**3D 화면이 이 새 필드를 읽도록 연결하는 작업은 프론트엔드에 남아 있습니다.**

## 검색 평가도 더 엄격하게

동료가 만든 Legal·Technical 14문항 및 Recall@5·MRR 평가를 유지하고 다음 검사를 추가했습니다.
여기서 Recall@5는 문항별 기대 근거 중 하나 이상을 찾은 비율입니다. 관련 조문 전체를 회수했다는 지표는 아닙니다.

- 법령은 반환한 **인용 위치**에서 정답 조문을 확인합니다. 다른 조문 본문에 제25조가 언급된 것만으로 통과시키지 않습니다.
- 제25조와 제25조의3, 서로 다른 판례 번호를 구분합니다.
- 검색 그룹 밖 문서가 섞이면 실패 처리하고, 잘못 섞인 기업 문서 제목은 평가 출력에서 가립니다.
- `required=true`인 핵심 질문이 실패하면 평균이 좋아도 평가 명령이 실패합니다.
- 잘못된 K·boolean 점수·문자열 형태의 정답 목록 등을 거부합니다.

현재 일반 법령 검색은 **6/7**, 기술문헌은 **7/7**, 추가 표현은 **5/8**입니다.
평균 지표가 기준을 넘더라도 핵심 허가 조문 질문이 실패하므로 `resource-rag evaluate`는 종료 코드 1을 반환합니다.
기술문헌은 검수 요약 검색이며 논문 원문 전체의 조건 이해나 전문가 판단 정확도를 평가한 것은 아닙니다.

조문 묶음·형태소 BM25 단독 검색도 비교했지만 일반 질문의 조문 회수 개선을 충분히 입증하지 못해 기본 검색에 채택하지 않았습니다.
기본 조문 직접 조회는 일반 RAG와 **다른 기능**이며 두 결과를 섞어서 검색 점수를 높이지 않았습니다.

최종 로컬 코드 검사는 실제 두 DB에서 **796개 + subtest 24개 통과·skip 0개**입니다.
69개 HTTP 시나리오의 세부 검사는 **358/360 통과**입니다. 이전보다 검사 수가 늘어난 것은
기본 조문·지도 집계·기술 검색 그룹 검사를 추가했기 때문입니다. 두 실패는 기존의 핵심 허가 조문 검색 문제입니다.
일반 검색의 그 실패를 기본 조문 직접 조회 성공으로 덮어쓰지 않았습니다.

다음에는 법률 전문가의 조문·예외 정답셋, 해당 공정의 실제 허가/신고·인수 증빙,
선택 시설 간 도로 경로와 견적·활동량이 필요합니다. 사용자 문서 OCR·증빙 검수·실제 3D 연동도 남아 있습니다.
`PASS`·최종 Top K·발주 승인은 계속 비활성 상태입니다.
