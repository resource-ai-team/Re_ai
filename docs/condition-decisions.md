# 조건을 바꾸며 검토하기 — 2026-10-29

구현한 것은 **원문에 있는 수탁 수치 조건 대조·우선 보완 자료·분리된 가정 실험·시설별 공정 묶음·변경 기록**이다.
현행 법규 적용이나 이번 로트 수용 가능성을 보장하는 기능이 아니다.

## 사용 순서

1. 기존 공정 후보 조사 후 문서·증빙에서 수탁 기준과 시료 성적서의 발췌를 확인한다.
2. **조건·변경**에서 후보·단계·항목을 선택한다.
3. 시설·공정에 적용되는 기준값·비교 방식·근거를 연결한다. 측정값은 이번 로트·이 공정 단계의 자료인지 확인한다.
4. 기준·측정값이 모두 유효하면 코드로 대조한다. 불일치는 후보의 수치 비교에서 제외하고 근거와 다음 행동을 표시한다.
5. 가정 수분·오염도 값으로 조건·지도만 비교한다. 저장본과 비교하며 닫기·다른 탭·새 저장본 조회 때 가정을 해제한다.

예시 `함수율 <= 2 %`, 측정 `함수율: 3 %`는 **가상 수치**다. 실제 시설의 기준으로 사용하면 안 된다.

## KG의 역할과 검증 범위

- 기존 KG의 시설 조건 항목 `moisture_pct`, `contamination_pct`, `quantity_kg`를 가져온다. 공정·시설·그래프 버전에 연결된 `condition_id`를 사용한다.
- 확인된 시설 수탁 수치 한도가 KG에 없으므로 임계값을 자동 생성하지 않는다. 사용자가 기준 원문과 적용 범위를 연결한다.
- 한국어 항목·명시적 비교 연산자·단위(%·kg·t·톤)를 제한적으로 읽는다. 비교 없는 숫자·추정·범위·모순 연산자는 기준으로 승격하지 않는다. 서로 다른 기준/관측값이 여러 개면 원문을 좁혀야 한다.
- 원문에 같은 수치·단위·비교 방식이 없으면 거절한다. 원문 진위·시험 정확성·실제 시설 적용성을 독립 검증한 것은 아니다.
- 확인 상태·가상 여부·평가 기준일 대비 유효기간·내용 해시를 대조한다. 내용·확인 변경은 미확인으로 되돌린다. 전송 허용만 바뀌는 경우에는 값 연결을 무효화하지 않는다.
- 소재·형태가 바뀌면 기준 적용을 재확인한다. 로트·발생지 입력이 바뀌면 이전 단계 측정값을 재사용하지 않는다.
- 발생지 문서의 확인값은 **첫 공정에만** 쓴다. 후속 단계에는 해당 단계 시료의 근거가 필요하다.

`met` = 제출 수치 기준 충족, `unmet` = 제출 기준 불일치, `unknown` = 근거/유효성 확인 필요.
수치가 맞아도 현행 허가·법규 적용·이번 로트 인수·여유 용량·인계 규격은 별도 검토로 남기며 `dispatch_approved=false`다.

## 우선 작업과 변경 기록

조건·계산 충돌 → 법규·인수 → 수탁 기준 → 단계별 측정값 순서로 정렬한다.
대상·담당 역할·필요 문서·변경될 수 있는 항목을 붙인다. 초기 작업 3개와 전체 조건·세부 질문을 함께 보존한다.
비용·확률·예상 수익이 없어 금전적 정보가치를 추정하지 않는다.
변경 전후 조건·수치 비교 상태·근거를 기록한다. 조건 보완은 로컬 재검사이며 KG/RAG/지도/모델을 반복 호출하지 않는다.

## API 계약

기존 내부 인증·tenant·actor·버전·동일 요청 처리를 유지한다. 정확한 타입·범위는 OpenAPI의 `ConditionsUpdate`, `ConditionRule`, `ConditionReading`, `WhatIfRequest`를 기준으로 한다.

| 요청 | 기능 |
|---|---|
| `PUT /workflow/cases/{id}/conditions` | 기준·측정 연결/해제. `expected_revision`, `Idempotency-Key` 필수 |
| `POST /workflow/cases/{id}/what-if` | 읽기 전용 조건 가정. `expected_revision` 필수. DB 저장·외부 호출 없음 |
| `GET /workflow/cases/{id}` | 이전 결과에도 새 조건 뷰를 읽을 때 계산. 저장 버전·이력은 유지 |

`conditions`에는 아래 배열을 선택적으로 넣는다. 중복 추가·같은 요청에서 추가/삭제를 함께 할 수 없다.

- `rules[]`: `condition_id`, 현재 대상의 `facility_id`, `operator`(le/lt/ge/gt/eq), `limit`(decimal string), `unit`(%/kg), `evidence_id`, `applicability_confirmed=true`.
- `readings[]`: `condition_id`, `value`(decimal string), `unit`, `evidence_id`, `same_lot_and_stage_confirmed=true`.
- `remove_rules[]`, `remove_readings[]`: 현재 조건 ID 목록. 문서 원본·과거 이력은 삭제하지 않는다.

확인·유효성 검사를 통과한 현재 검토의 근거를 써야 한다. %는 0~100이며 kg 조건의 톤 원문은 kg로 환산한다.
응답의 `evaluation.decision_support`에 조건·후보 보류 사유·우선 작업을,
`last_decision_change`에 전후 조건·수치 비교 상태·근거 ID를 반환한다. 보고서에도 남긴다.

`what-if` 본문 예시:

```json
{
  "expected_revision": 12,
  "readings": [{"condition_id": "응답의 조건 ID", "value": "1", "unit": "%"}]
}
```

현재 가정 실험은 **수분·오염도 %만** 지원한다. 물량 변경은 물질수지·활동량 모형이 필요해 거절한다.
응답은 `scope=hypothetical_not_saved_or_observed`, 기준 검토·버전, 가정, 조건 대조, 변화 목록이다.
`cost_and_carbon=null`: 수분에 따른 수율·건조 전력·단가 효과를 추정하지 않는다. 다른 기업·검토·지난 버전의 가정을 적용할 수 없다.

## 지도·운송·Critic

정확한 시설 ID가 같은 공정은 한 건물 안에 묶고 후보·순서를 보존한다. 이름이 비슷하다고 합치지 않는다.
내부 인계의 확인 항목도 시설에 연결하며 원래 단계/인계 ID를 유지한다. 초원 좌표는 실제 위치가 아니다.
KG가 내부 이동 후보로 기록했고 선택 시설 ID·게이트가 같은 구간은 공개 도로 API에서 제외한다.
내부 이동 거리를 0으로 채우지 않고 별도 활동량 미확인으로 남긴다. 외부 도로 완료와 전체 이동 완료를 구분한다.

확인·전송 허용한 기준·측정 근거에 한해 조건·대상 단계·연산자·수치·단위·대조 상태를 Astra에 포함할 수 있다.
한쪽 근거가 비허용이면 그 조건 묶음을 전달하지 않는다. 확인자·개인 프롬프트·주소·원본은 자동 전송하지 않는다.
인용·후보 범위를 대조하고 모델 의문은 추가 확인으로 남긴다. 이번 구현에서는 유료 모델·OCR·지도 호출을 하지 않았다.

`scripts/evaluate_decision_scenarios.py`는 실제 로컬 KG/RAG/Postgres + **가상 로트·기준·측정값**으로 다음을 재현한다.

`근거 부족 → 불일치 → 가정 충족/미저장 → 원문 변경으로 미확인 → 재확인 후 수치 충족/허가 보류`

브라우저는 가상 기준 0.2%, 문서 측정 0.3%, 가정 0.1%로 조건·지도 변화와 저장 버전 유지를 확인한다. 실제 업체 기준이 아니다.

남은 일은 실제 수탁·시료 자료 검수, 법규/인수 조건 구조화와 전문가 확인, 수율·비용·탄소 인과 모형,
오류별 KG/RAG 부분 재조회, 같은 모델·자료를 쓴 일반 RAG와의 독립 비교다.
이번 구현을 전체 차별화 계획 완료나 판매 가능성 입증으로 표현하지 않는다.
