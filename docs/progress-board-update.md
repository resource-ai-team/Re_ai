**완료 기준:** 추출값에 원문 위치가 붙고 사용자 확인값·모델 추출값을 구분한다. 없는 성분·위치·기존 처리 경로를 만들지 않는다. 입력 수정 후 이전 결과가 새 분석에 섞이지 않는다.

**의존:** 문서 처리, 공통 입력 계약, Re_server·사용자 검수 화면.

**PR·문서 근거:** [확정 파이프라인](pipeline-baseline.md), [API](api.md), `src/resource_ai/api/`.

### 07. [계산] 후보별 비용·탄소 계산 및 비교 조건 검수

**목표:** 같은 처리 물량·범위에서 경로별 순비용과 탄소를 재현 가능한 계산으로 구한다.

**현재 된 것:** PR #19의 `/analysis/compare-scenarios`가 제출된 활동량·단가/계수를 Decimal로 계산한다. 공정·초기/중간 운송·잔재물·매각 수익의 누락과 단위·기간·지역·경계를 검사한다. 일부만 있으면 소계와 미완성 총계를 구분한다.

**남은 일:** 적합 후보와 실제 견적·도로거리·LCI 연결, 원문 수치·적용성 검수, 수율·물질수지·불확실성 검토. 제출한 URL과 계수가 있다는 사실만으로 실제 자료의 진위를 보장하지 않는다.

**완료 기준:** 식·단위·활동량·계수·출처가 연결되고 누락을 0으로 채우지 않는다. 같은 기능단위·시점·시스템 경계만 비교한다. 근거 없는 기존 경로 대비 절감량은 표시하지 않는다.

**의존:** 법규·시설 검증, 실제 비용·LCI·운송·잔재물 자료, 공통 수치 계약.

**PR·문서 근거:** [#19](https://github.com/resource-ai-team/Re_ai/pull/19), [계산 범위·가상 예제](candidate-analysis.md), `src/resource_ai/calculators/scenarios.py`.

### 08. [출력] 최종 공정·시설 추천·근거 보고서·지도 연동

**목표:** 검증을 통과한 공정·시설 조합과 확인할 일을 보고서·지도에서 이해하기 쉽게 보여준다.

**현재 된 것:** 별도 3D 프로토타입이 있다. 새 AI 파이프라인의 최종 결과·PDF·지도 통합은 아직 없다.

**남은 일:** Re_server 응답 연결, 검증 통과 최대 K개·보류/제외 후보 구분, 공정·인계 구간별 리스크·근거·다음 행동 표시, 보고서 생성·다운로드.

**완료 기준:** 리스크가 올바른 단계·운송 구간에 표시되고 미확인을 실제 사고처럼 보이지 않는다. 통과 후보가 없으면 없다고 표시하며 K개를 억지로 채우지 않는다. 보고서의 수치·근거가 같은 실행 결과와 일치한다.

**의존:** 비교·Critic·Router 최종 상태, 전체 실행 이력, Re_server·Re_client.

**PR·문서 근거:** [확정 파이프라인](pipeline-baseline.md), [저장소 역할·호출 경계](../README.md), [구현 경계](candidate-analysis.md).

### 09. [평가] 실제 사례 정답셋 및 전체 파이프라인 검증

**목표:** 어디서 후보를 놓치거나 잘못 판단하는지 실제 사례와 회귀 검사로 확인한다.

**현재 된 것:** 가상 입력 회귀 검사, 실제 Neo4j·PostgreSQL 경계 검사, 5소재 KG/API·가상 산술 검사 28/28이 있다. 현장·전문가가 검수한 실제 정답셋은 없다.

**남은 일:** 실제 공장·폐자원 사례의 기대 경로·조건·근거·수치 확보, 전문가 검수, 후보 누락·잘못된 통과/탈락·근거 정확성·재실행·실패 처리 평가.

**완료 기준:** 데이터·코드·그래프·평가 버전을 고정하고 사례별 실패 원인을 볼 수 있다. 가상/실제 자료와 DB 연결/의미 검색/법규 정확도 검증을 구분한다. 테스트 통과율을 추천 정확도로 부르지 않는다.

**의존:** 각 단계의 결과 계약·평가용 실제 자료·전문가 검수, 실행 환경.

### 10. [실행] 전체 파이프라인 상태·오류·이력·서버 연동

**목표:** 각 모듈을 같은 분석 요청으로 연결하고 진행 상태·실패·결과 이력을 관리한다.

**현재 된 것:** `/analysis/research`가 동기식으로 KG→시설 공개 조건→법령 조사를 연결한다. 페이지/버전 검사, 검색 예산·DB 연결 시간 제한·실패 보존이 있다. 전체 오케스트레이터는 아직 골격이다.

**남은 일:** 입력→검증→계산→비교→Critic·Router→출력 연결, 영구 실행 이력, 단계별 입력/출력·버전, 진행 이벤트, 시간 제한·취소·중복 요청·서버 재시작 처리와 Re_server 연동.

**완료 기준:** 성공·실패·시간 초과·취소·중복·복구를 재현하고 다른 요청 결과가 섞이지 않는다. Router가 정한 재실행을 수행하되 완료하지 않은 단계를 완료로 표시하지 않는다.

**의존:** 모든 단계의 모듈 계약, 상태 저장소, Router 판정, Re_server 이벤트 계약.

**PR·문서 근거:** [#19](https://github.com/resource-ai-team/Re_ai/pull/19), [현재 분석 연결](candidate-analysis.md), [전체 설계](pipeline-baseline.md), `src/resource_ai/agents/research.py`.

### 12. [비교] 적합 후보 Pareto 비교 및 잠정 Top K

**현재 된 것:** 별도 수치 시나리오의 Pareto 층 계산이 PR #19에 있다. 검증된 실제 후보의 잠정 Top K·최종 추천은 아직 없다.

**남은 일:** 적합성 결과·비교 가능한 총계 연결, 명시된 선정 기준·동점 처리, 잠정 K개 선정과 전체 후보·제외/보류 이유 전달. 임의 사용자 우선순위나 가중치를 만들지 않는다.

**완료 기준:** 지배 관계와 선택 기준을 재현할 수 있다. Pareto 집합을 절대 순위로 표현하지 않으며, 전체 후보를 Critic에 넘긴다. 이 단계의 결과는 잠정이며 최종 추천이 아니다.

**의존:** 검수된 적합성·비용·탄소·비교 경계, 최종 출력 계약.

### 13. [Critic] 경로·시설·근거·계산·추천 독립 검증

**현재 된 것:** 전체 설계에 역할·입력·재검증 약속을 기록했다. 실제 Critic 실행기는 미구현이다.

**남은 일:** 후보·전처리 누락, 시설 연결·허가·예외 오류, 단가·운송·탄소 경계·비교 오류를 확인하고 후보/단계/구간/근거 ID·오류 유형·원인 단계로 지적한다. 단순 찬반 토론·다수결로 결론내리지 않는다.

**완료 기준:** 전체 후보·보류/제외 이유를 검사하고 의도적으로 심은 오류를 찾는다. 근거 없는 의심과 확인된 오류를 구분하고 정상 후보를 불필요하게 제거하지 않는다.

**의존:** 전체 KG 후보, 검증·계산 근거, 비교표·잠정 Top K, 공통 오류 계약.

### 14. [Router] PASS·REVISE·REVIEW 및 부분 재실행

**목표:** 검증 결과에 따라 통과·수정·전문가 검토를 분기하고 필요한 단계만 다시 실행한다.

**현재 된 것:** 설계만 있다. 현재 조사 API의 고정 REVIEW는 전체 Router 구현이 아니다.

**남은 일:** 코드로 분기·재시도 한도 제어, KG/검증/계산/비교의 원인 단계 지정, 영향받은 후속 결과 무효화·재계산, Critic 재검증, 핵심 미해결 조건의 REVIEW 처리.

**완료 기준:** KG 오류는 KG부터, 법규·시설 오류는 검증부터, 수치·경계 오류는 계산부터, 비교 오류는 비교부터 갱신한다. 이전 결과가 남아 최종 통과하지 않고 무한 반복을 막는다. 허가·인수 미확인은 추천 확정을 보류한다.

**의존:** Critic의 구조화 지적, 전체 실행기의 재실행·상태 저장 기능, 각 단계 의존 관계.

**PR·문서 근거:** [분기·부분 재실행 설계](pipeline-baseline.md). 구현 PR은 아직 없다.
