# AI 진행보드 개편안

**Notion 미반영.** 브라우저 제어 도구가 시작 전에 `failed to write kernel assets`로 실패하고, 연결된 Notion에서는 원본 보드가 404이므로 실제 행·담당자·상태값을 읽거나 수정하지 못했다. 아래는 코드와 확정 아키텍처를 대조한 수정 원고다. 기존 카드와 대조한 뒤 같은 목적의 카드를 수정하고, 중복 생성하지 않는다.

## 건드리지 않을 항목

- 완료한 첫 번째 **KG 온톨로지·그래프 구축** 카드
- 완료한 **RAG 두 카드**

위 세 카드의 제목·본문·상태·담당자·날짜를 모두 보존한다. 기존 보드의 정확한 카드 ID는 아직 확인하지 못했다. 다른 카드도 담당자·일정을 임의로 바꾸지 않는다.

## 새 흐름

입력 정리 → KG 공정·시설 후보 전체 탐색 → 법규·시설 검증 → 비용·탄소 계산 → Pareto 비교·잠정 Top K → 독립 Critic → PASS / REVISE / REVIEW → 보고서·공정 지도

KG는 가능한 조사 후보를 만들고, 법규·시설 검증은 실행 조건을 확인한다. 계산은 Python이 수행한다. Critic은 전체 후보와 보류·제외 사유까지 확인한다. 단순한 에이전트 찬반 토론·다수결은 핵심 흐름에서 뺀다.

## 카드별 본문

### [입력] 자연어·문서를 폐자원 항목으로 정리

**목표:** 사용자의 요청과 분석서를 KG가 읽을 수 있는 입력으로 바꾼다.

- 종류·성상·물량·발생 위치·성분·오염·수분·제약을 추출하고 원문 위치를 붙인다.
- Azure Document Intelligence 등 OCR 공급자는 교체할 수 있게 연결한다. 모델·지원 리소스는 확정 전이다.
- **완료 기준:** 없는 정보는 미확인으로 남고, 숫자·단위·추출 근거를 사용자가 검수할 수 있다. 기존 처리 경로를 만들어내지 않는다.

### [입력] 누락·모순 확인과 사용자 검수

- 애매한 수지명, 물량 단위, 문서 간 모순을 질문으로 돌려준다.
- 사용자가 확인한 사실과 모델 추출값·예상값을 구분한다.
- **완료 기준:** 입력 수정 이력이 남고, 다른 입력의 결과가 같은 분석에 섞이지 않는다.

### [KG] 전체 후보 조회·근거 묶음

- W2RKG 문헌과 조건부 공정 후보를 모든 페이지에서 읽는다.
- 후보 ID·근거·리스크 대상·미확인·그래프 버전을 보존한다. KG 단계에서 최종 K개를 고르지 않는다.
- **완료 기준:** 전체 건수·조회 한도·누락 여부를 확인하고, 조회 도중 그래프가 바뀌면 혼합하지 않는다.
- **근거:** [PR #11](https://github.com/resource-ai-team/Re_ai/pull/11). 기존 완료 온톨로지 카드는 수정하지 않고 선행 작업으로 참조한다.

### [KG] 공정 순서·시설 조합 후보 탐색

- 출처가 있는 소재 상태 전이를 따라 전처리·후속 공정·시설 조합·인계 구간을 만든다.
- 문헌의 쉼표 목록을 공정 순서로 해석하지 않는다. 시설 역할 가설과 사업장 직접 근거를 구분한다.
- **완료 기준:** 각 단계·시설·인계 구간의 근거와 미확인이 따라오고, 최종 추천·인수 승인을 하지 않는다.
- **근거:** [PR #13](https://github.com/resource-ai-team/Re_ai/pull/13).

### [KG] 국내 시설 명부 검색

- 공식 폐기물 코드·설비 단어·직선거리로 추가 조사 대상을 찾는다.
- 등록 레코드를 고유 기업 수로 세지 않는다. 이름이 비슷하다고 자동 병합하거나 공정 경로에 넣지 않는다.
- **완료 기준:** 검색 이유·출처·수집 범위·현행 허가와 인수 미확인이 함께 나온다.
- **근거:** [PR #15](https://github.com/resource-ai-team/Re_ai/pull/15). 9,604개는 확보한 등록 레코드 수다.

### [KG] 시설 공개 조건 대조·공정별 확인 과제

- 공개 투입물 예시·명시적 제외 정책을 구분해서 로트와 대조한다.
- 수분·오염·물량 한도가 없으면 기준을 만들지 않는다. 후속 단계에는 원래 시료 측정값을 복사하지 않는다.
- **완료 기준:** 불일치·미확인이 공정 ID나 인계 구간 ID에 붙고, 공개 예시 목록에 없다는 이유만으로 탈락하지 않는다.
- **근거:** [PR #17](https://github.com/resource-ai-team/Re_ai/pull/17). 현행 허가·실제 수용 검증 완료는 아니다.

### [KG 데이터] 실제 사업장·공정 수행 근거 보강

- 사업장 식별자·주소·수행 공정·투입/산출 규격·출처·확인일을 확보한다.
- 문헌 기술, 기업 전체 소개, 특정 시설 직접 근거를 따로 관리한다.
- **완료 기준:** 공정–시설 연결마다 출처가 있고, 조사 후보에서 검증 후보로 옮긴 이유를 설명할 수 있다.

### [검증] 후보별 법령 조사 연결

- KG의 각 공정·시설·인계 구간에서 필요한 질문을 만들고 기존 법령 RAG를 호출한다.
- 같은 질문은 한 실행 내에서 재사용하고, 실패·검색 한도·근거 없음도 기록한다.
- **완료 기준:** 모든 후보의 조사 범위와 원문·조문·시행일이 추적된다. 검색만 했다고 적합으로 표시하지 않는다.
- **의존:** 기존 완료 RAG 두 카드와 KG 경로 탐색. 완료 RAG 카드는 변경하지 않는다.
- **이번 구현:** `/analysis/research`. 현재 KG 공정·시설 조합의 전체 페이지→공개 조건→법령 조사 과제·검색 연결. 적용성 Auditor는 미구현이며 최종 결과는 REVIEW다. [구현 설명](candidate-analysis.md), [작업 #18](https://github.com/resource-ai-team/Re_ai/issues/18).

### [검증] 법규 적용성·원문·예외 Auditor

- 조사 주장이 원문에서 지지되는지, 시행일·폐기물 분류·재활용 유형·예외·사업장 범위가 맞는지 확인한다.
- 필요하면 제한된 ReAct 도구 호출로 보완한다. 모델이 임의로 법적 통과를 확정하지 않게 한다.
- **완료 기준:** 적용 사실·근거·예외·미확인을 구조화하고, 반대 근거·근거 없는 주장·미래 시행 조문을 시험한다.

### [검증] 현행 허가·투입 규격·실제 인수 확인

- 관할기관 허가 범위, 해당 로트의 규격·일정·수탁 가능 물량·서면 인수 조건을 확보한다.
- 공개 명부의 등록 상태를 현재 허가·여유 용량으로 치환하지 않는다. 외부 연락은 별도 지시가 있을 때만 한다.
- **완료 기준:** 사업장·품목·시점에 묶인 확인 자료가 있거나, 확인 필요와 다음 행동이 명시된다.

### [검증] 적합·부적합·확인 필요 종합 판정

- 검수된 필수조건의 충족·불충족·미확인을 코드로 종합한다.
- 부적합은 근거 있는 필수조건 위반일 때만 사용한다. 미확인은 통과도 탈락도 아니다.
- **완료 기준:** 후보를 숨기지 않고 판정·근거·보류 이유를 보존한다. 허가·인수 미확인 후보를 최종 추천하지 않는다.

### [계산] 비용 근거·운송거리·순비용 계산

- 처리·전처리·운송·잔재물 비용과 매각 수익을 분리한다.
- 실제 견적의 시점·물량·지역·단위를 보존하고, 도로거리와 직선거리를 구분한다.
- **완료 기준:** Python 계산을 재현할 수 있고, 누락된 비용은 0원으로 채우지 않는다. 근거 있는 0원은 별도로 명시한다.
- **이번 구현:** `/analysis/compare-scenarios`에서 제출한 활동량·단가를 곱하고 순비용·누락 항목을 반환한다. 실제 단가·도로거리 확보나 KG 후보와의 자동 연결 완료는 아니다.

### [계산] LCI·배출계수·탄소 계산

- 처리·전력·운송·잔재물의 활동량과 계수를 연결한다. LCI 원본의 사용·전송·재배포 조건을 확인한다.
- 단계별 회수율·산출량과 기능단위·지역·연도·배분·시스템 경계를 기록한다.
- **완료 기준:** 계산식·계수 출처를 추적하고, 근거 없는 탄소절감량·기존 처리 대비 절감률을 표시하지 않는다.
- **이번 구현:** 제출한 활동량·계수·단위·근거 범위의 산술 검사와 탄소 합산. 사용 가능한 LCI 원문·계수의 내용 검증·실제 경로 적용은 후속이다.

### [비교] 물량·단위·연도·경계 통일

- 같은 입력 물량의 처리라는 기능을 기준으로 비용·탄소 범위를 맞춘다.
- 서로 다른 경계·기술·시점의 LCI 값이나 중간재 산출값을 그대로 비교하지 않는다.
- **완료 기준:** 비교 가능한 항목과 불가능한 이유를 먼저 판단하고, 부분 자료 합계를 전체 총액으로 표시하지 않는다.

### [비교] Pareto 비교·잠정 Top K

- 적합성과 비교 기준을 충족한 후보에서 비용–탄소 Pareto 후보를 계산한다.
- 명시되지 않은 사용자 우선순위·가중치를 만들지 않는다. Pareto는 하나의 절대 순위가 아니다.
- **완료 기준:** 지배 관계·동점·선정 기준을 설명하고, 전체 풀과 제외·보류 목록을 Critic에 넘긴다. 결과는 잠정이다.
- **이번 구현:** 선언한 같은 경계의 수치 시나리오에 Pareto 층을 계산한다. 법규·인수 검증을 통과한 후보의 잠정 Top K는 아직 없다.

### [Critic] 경로·시설·근거·계산·추천 독립 검증

- 후보 누락, 전처리 누락, 시설 연결 오류, 허가·예외, 누락 비용, 탄소 경계, 비교·순위를 독립 확인한다.
- 지적에 후보·공정/구간·근거 ID와 원인 단계를 붙인다. 단순 의견 차이와 근거로 확인한 오류를 구분한다.
- **완료 기준:** 의도적으로 심은 경로·근거·계산 오류를 찾고, 정상 후보를 불필요하게 제거하지 않는다.

### [Router] 원인 단계 재실행·후속 결과 무효화

- PASS / REVISE / REVIEW를 코드로 제어한다.
- KG 오류는 KG부터, 법규 오류는 검증부터, 계산 오류는 계산부터 다시 실행한다. 영향받은 결과를 무효화하고 Critic을 다시 실행한다.
- **완료 기준:** 무한 반복을 막고 재시도 상한·실행 이력을 남긴다. 핵심 허가·인수 미확인은 REVIEW다.

### [출력] 최종 추천·근거·미확인 보고서와 지도 연동

- 검증을 통과한 최대 K개 공정·시설 조합과 근거·수치·리스크·다음 행동을 반환한다.
- 확인 필요·제외 후보는 별도로 보존한다. 프론트는 Re_server를 통해 호출한다.
- **완료 기준:** 리스크가 올바른 공정/구간에 표시되고, 미확인 조건을 실제 사고처럼 표현하지 않는다. 통과 후보가 없으면 없다고 보여준다.

### [평가] 실제 사례 정답셋·통합 회귀 검증

- 지금의 가상 입력·문서 기대 결과 회귀셋과 실제 공장·전문가 검수 정답셋을 분리한다.
- 후보 누락, 잘못된 탈락·통과, 근거 정확성, 비용·탄소 재현성, 재실행·실패 처리를 측정한다.
- **완료 기준:** 데이터·코드·그래프·평가 버전을 고정하고 사례별 실패 원인을 볼 수 있다. 테스트 통과율을 추천 정확도로 부르지 않는다.

## 우선 진행 순서

1. KG와 기존 법령 RAG를 후보 단위 실행기로 연결한다.
2. 비용·탄소 입력 계약과 계산·비교 가능성 검사를 구현한다.
3. 허가·규격·인수·견적·LCI 자료를 확보하고 Auditor·규칙을 검수한다.
4. 적합 후보의 잠정 Top K와 독립 Critic·부분 재실행을 연결한다.
5. Re_server·보고서·지도와 통합하고 실제 검수 사례로 평가한다.
