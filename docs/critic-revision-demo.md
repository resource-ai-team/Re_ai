# Critic은 어디까지 됐나요?

아래는 처음 만든 **코드 전용 재생 데모**입니다. 이후 지원받은 Azure GPT로 실제 비판·수정·재검사도 실행했습니다. [새 실제 GPT 기록](azure-critic-live.md)을 함께 보세요.

**오류를 찾고 다시 시작할 단계를 정하는 것까지 구현됐습니다.** GPT 추가 비판의 연결 코드도 있지만 현재 실행 설정에서는 꺼져 있습니다. 실제 GPT의 비판 정확도는 아직 평가하지 않았습니다.

| 기능 | 현재 상태 |
| --- | --- |
| 코드 Critic | 공정 연결·수치 연결·단위·산술·비교 오류와 미확인 근거 검사 |
| Router | `REVISE`와 다시 시작할 단계·영향받는 후속 단계 표시 |
| GPT Critic | Azure Astra/high 연결·인용 검사 구현, 실제 호출은 비활성 |
| 서비스의 자동 수정 루프 | 아직 미구현. API의 `automatic_reexecution=false` 유지 |
| 이번 재생 데모 | 실제 엔진을 호출한 3회 검사와 허용한 2회 수정을 기록해서 재생 |

## 실제로 돌린 과정

가상 공장의 **PP 스크랩 3톤**으로 현재 Neo4j 공정 후보 3개와 로컬 법령·기술 RAG를 조회했습니다. 오류를 보기 위해 **복사한 초안에서 인계 구간 하나를 삭제**하고, **가상 운송 단가 20,000 KRW/t를 kg 활동량에 연결**했습니다. DB 원본은 수정하지 않았습니다.

| 회차 | 실제 검사 결과 | 수행한 조치 |
| --- | --- | --- |
| 1 | 검사 오류 5건, `REVISE`, KG부터 다시 시작 | KG·법령·기술 근거를 새로 조회 |
| 2 | 연결 오류 해소, 단위 오류 1건, `REVISE` | 20,000 KRW/t를 20 KRW/kg로 환산 |
| 3 | 주입 오류 0건, 미확인 사항 남음, `REVIEW` | 비용·탄소·비교를 다시 계산하고 사람 확인으로 정지 |

5건은 두 종류의 주입 문제에 대한 연결·계산 검사 기록입니다. 실제 산업 현장에서 다섯 가지 오류를 발견했다는 의미는 아닙니다. 금액·활동량·배출계수는 모두 가상이며 실제 견적이나 LCI를 사용한 경제성 평가가 아닙니다.

이 데모의 수정은 개발용 실행기가 Critic의 오류 코드를 보고 허용한 동작만 수행합니다. 최대 수정은 2회입니다. 그래프 버전이 달라지거나 지원하지 않는 오류·단위가 나오면 멈추고, 기존 수치를 새 경로에 임의로 재연결하지 않습니다. 가격·배출계수·허가·인수 정보를 만들어 채우지 않습니다.

**GPT가 자율적으로 고친 실행은 아닙니다.** 실제 코드 Critic과 계산·검색 모듈이 동작한 기록입니다. 재생 화면의 버튼은 저장한 기록을 보여주며, 클릭할 때마다 모델이나 엔진을 호출하지 않습니다.

## 다시 실행

기존 KG·RAG와 E5를 준비한 환경에서 프로젝트 루트에서 실행합니다.

```powershell
python scripts/replay_critic_revision.py --output data/local/critic-replay.json --visual data/local/critic-replay.html
```

`examples/critic-revision.html`에 실행 결과를 넣어 재생 화면을 만듭니다. DB 원본을 변경하거나 GPT·지도 API를 활성화하지 않습니다. 지원하는 입력은 이 시연의 PP 스크랩 3,000kg입니다.

다음 구현은 이 구조를 API에 연결하는 작업입니다. **근거가 있는 재검색·재계산**과 **사용자·전문가가 채울 정보**를 구분하고, 허용 동작·재시도 한도·버전 대조·변경 이력을 갖춘 뒤 연결해야 합니다. 실제 GPT 반박을 사용하려면 별도로 활성화하고 품질을 검증해야 합니다.
