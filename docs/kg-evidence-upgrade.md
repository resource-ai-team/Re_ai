2026-10-21 기준입니다. KG가 만드는 것은 **조사할 공정·시설 후보**이며, 이번 로트를 실제로 받을 수 있다는 승인이 아닙니다.

## 종이 공정 예시

아래는 [한솔페이퍼텍 공식 생산공정](https://www.hansolpapertech.com/intro/present.jsp)을 확인해 작성한 순서입니다.
5개 묶음 안의 `operation_steps`를 펼치면 원문의 10개 작업 순서가 유지됩니다.

```mermaid
flowchart LR
    A[회수 고지] --> B[1 해리]
    B --> C[2 정선·농축·고해]
    C --> D[3 지필형성·압착탈수]
    D --> E[4 건조·광택]
    E --> F[5 권취·재단]
    F --> G[골판지 원지]
```

담양 사업장의 공개 생산공정에 연결했습니다. 특정 등급·코팅·오염 고지의 인수, 현행 허가,
이번 일정의 가동 여부·회수율·용량·단가는 확인하지 않았습니다.
고지 외 펄프·첨가물·에너지와 잔재물도 필요하므로 투입량을 그대로 제품량으로 계산하지 않습니다.

기존 진입·산출 상태 key는 유지했습니다. 첫 시설 조건 대조에는 이제
`hansol-damyang--paper-pulping`을 사용합니다. 기존 `hansol-damyang--paper-board`는 마지막 권취·재단 단계입니다.
이전의 단일 단계 경로와 새 경로의 ID·커서는 다릅니다. 서버·화면에서는 key와 순서를 고정하지 말고 응답의 단계를 읽어야 합니다.

배포 자료는 직접 작성한 짧은 사실 요약·구조화 관계이며, 원본 문서·사진·도표는 제외합니다.

[한국환경공단 영농폐비닐 공정](https://www.keco.or.kr/group06/lay1/S301T793C908/contents.do)도 검토했지만 운영 KG에는 넣지 않았습니다.
영농폐비닐과 공장 필름을 구분할 입력 범위, 사업장별 실제 공정 근거가 먼저 필요합니다.
기관의 일반 공정도를 모든 시설의 설비 증거로 복사하지 않습니다.

## 연결 상태 확인 API

```text
GET /kg/planning-coverage
```

활성 Neo4j 세대에서 실제 자료를 읽고 번들과 대조한 뒤 다음을 반환합니다.

- 현재 자료 수, 조회 세대·참조 해시, 출처 확인일·원본/검수 기록 해시 구분
- 진입 상태에서 도달하지 못하는 전이·산출물
- 산출물까지 이어지지 않는 가지와 비산출물 막다른 상태
- 도달 가능한 전이 중 시설 연결이 없는 항목, 공정 연결이 없는 시설
- 실제 사업장 공개 근거와 기업 전체 소개에 따른 사업장 가설의 구분

이는 **등록한 그래프의 연결 검사**입니다. 현실의 모든 경로를 조사했다는 뜻도, 경로가 실행 가능하다는 뜻도 아닙니다.
Neo4j 장애·미적재·번들 불일치는 `503`이며 파일로 대신 결과를 만들지 않습니다.

후보 응답의 `search_scope.coverage_diagnostics`에도 입력 시작 상태 기준의 진단을 넣었습니다.
사용자가 중간 상태를 목표로 골랐다는 이유로 정상적인 후속 공정을 오류라고 표시하지 않습니다.
시설 key가 없는 인계는 `unresolved_handover_candidate`, `facility_identity_resolved=false`로 표시합니다.
후속 Critic이 이 정보를 소비하는 전체 검증·수정 흐름은 아직 구현 전입니다.

## PE와 출처를 읽는 방법

`material_scope`는 `search_family=pe`, `supplied_subtype=hdpe`처럼 조회 소재군과 입력 수지를 구분합니다.
HDPE·LDPE·LLDPE·MDPE와 대응 한글 명칭을 인식하지만, 후보는 여전히 PE 소재군 수준입니다.
`subtype_applicability_verified=false`이며 후속 단계도 등급 확인을 요구합니다.
앞 단계의 수지·성분·수분을 후속 단계의 실측값으로 복사하지 않습니다.

출처의 `supported_records`는 **검수자가 선언한 연결 범위**입니다. 존재하지 않는 항목이나 범위 밖 출처 연결은 검증에 실패합니다.
유효한 출처 ID라는 이유만으로 엉뚱한 전이에 붙이는 실수를 막지만, 원문 내용의 진위를 자동 판독하는 기능은 아닙니다.
새 근거를 추가할 때 원문·위치·적용 범위를 사람이 확인해야 합니다.

## 적용과 남은 일

기존 DB에는 다시 적재해야 합니다. 새 세대를 검사한 후 활성화하며 이전 세대는 보존합니다.

```bash
resource-kg validate
resource-kg import --rebuild
resource-kg audit
python scripts/evaluate_process_plans.py --output docs/evaluation/kg-plans-evidence-2026-10-21.json
```

탐색 알고리즘 표시는 `typed-state-facility-dfs-v2`입니다. 응답의 기존 필드를 삭제하지 않고 진단·자료 범위를 추가했습니다.
API와 공정 단계 의미 변경은 서버 담당자 리뷰 후 병합합니다.

`REVIEW`를 반환하는 경계를 확인했습니다. 실제 pgvector 적재·검색 성공과 법규 적용성 검수는 별도 확인이 필요합니다.
