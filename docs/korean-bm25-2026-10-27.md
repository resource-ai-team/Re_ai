# 한국어 법령 검색 추가

**비슷한 의미를 찾는 E5 검색에, 한국어 핵심 단어를 찾는 BM25 검색을 함께 사용할 수 있습니다.** 법령을 추가 수집하거나 임베딩 모델을 교체한 작업은 아닙니다. 기존 PostgreSQL·pgvector, E5 384차원, 공식 법령·고시 98문서를 사용합니다.

## 무엇을 바꿨나요?

1. **한국어 단어로 검색합니다.** Kiwi로 조사 등을 분리하고 명사·복합어를 찾습니다. 드문 단어, 제목·조문 제목의 일치, 색인 길이를 점수에 반영합니다. 긴 지침에 일반 단어가 많다는 이유만으로 순위가 높아지는 문제를 줄입니다.
2. **같은 조문에 여러 번 투표하지 않습니다.** E5와 BM25가 같은 조문의 다른 항을 찾아도 하나의 조문으로 합칩니다. 법령명·버전·출처·조문이 같을 때만 묶고, 가지 조문·다른 버전·판례는 구분합니다. 반환한 조각의 원문·메타데이터는 유지합니다.
3. **보충 근거가 직접 검색 결과를 밀어내는 것을 줄입니다.** 새 방식은 검색한 지침 본문과 목적에서 명시한 인용도 확인합니다. 같은 현재 공개 원문에서 확인한 별칭만 사용하며, 보충 근거는 인용된 법률을 우선해 최대 한 개를 표시합니다. 나머지 문맥은 기존 문맥 조회로 보충합니다.
4. **색인 준비 상태를 검사합니다.** 공개 현행 법령·판례 22,071조각이 모두 색인되어 있습니다. 재적재할 때 만들어지지 않은 색인의 이전 메타데이터를 지우고, 색인 열이 비어 있으면 다시 만듭니다. 기업 문서는 이 검색에 포함하지 않습니다.

질문을 특정 정답 조문으로 연결하는 목록은 추가하지 않았습니다. 출처의 인용 연결은 법적 적용성 판정이 아닙니다.

**이전에 놓친 여섯 질문은 모두 찾았지만, 원래 찾던 배출자 의무 질문 한 개가 밀렸습니다.** “처리업체로 넘긴 후에도 발생 사업자가 확인해야 할 법적 의무가 있나?”라는 질문에서 기대한 폐기물관리법 제17조가 Top 5에서 빠집니다. 파이프라인에는 제17조를 포함한 기본 근거 직접 조회도 있지만, 일반 검색의 이 실패를 해결한 것으로 보지는 않습니다.

추가 표현 검사에서는 경매로 인수한 공장의 방치폐기물 책임 질문도 기존에 찾던 판례를 놓쳤습니다. 위탁자의 확인 절차 질문은 기존과 새 방식 모두 실패했습니다. 30문항의 평균 개선만 보고 전체 설정을 교체하지 않은 이유입니다.

새 질문에서는 두 방식 모두 연간 실적 보고 조문을 놓쳤습니다. 이 질문의 기대 근거는 폐기물관리법 제38조입니다. **새 질문 결과를 보고 알고리즘을 다시 조정하지 않았습니다.**

이전 `retrieval_study_v1`의 dev/test 구분은 남겨두었지만, 이제 전체 질문을 수정·선택에 사용했습니다. **독립 검증셋이 아닌 회귀검사**입니다. 새 8문항도 개발자가 법령 원문을 보고 작성했으며 전문가·블라인드 평가는 아닙니다. 수치는 기대 조문이 Top 5에 있는지이며, 제품의 법률 정확도가 아닙니다.

같은 CPU에서 50문항 전체의 요청 중앙값은 기존 0.567초, 새 방식 1.156초였습니다. 모델 초기 로딩은 제외하며, 기술 문헌 검색도 포함한 관측값입니다. 동시 사용자 부하 시험이나 지연 보장이 아닙니다.

## 어떻게 사용하나요?

**전체 기본값은 기존 방식으로 유지합니다.** 일부 질문의 저하가 있고 추가 로컬 패키지·색인 준비도 필요하기 때문입니다. 선택 기능은 `GET /rag/search`와 `/analysis/site-review`의 LEGAL 검색에서 사용할 수 있습니다. TECHNICAL·COMPANY 검색은 기존 방식을 사용합니다.

프로젝트 루트에서 실행합니다.

```powershell
python -m pip install -e ".[embeddings,korean-lexical]"
resource-rag init-db
python scripts/build_korean_legal_index.py --output data/official/korean-index.json
python scripts/build_korean_legal_index.py --check-only --output data/official/korean-index-check.json
```

`--check-only`는 읽기 전용입니다. 공개 현행 코퍼스가 비어 있거나 누락이 있으면 종료 코드 1을 반환합니다. 원문·벡터를 다시 적재하지 않습니다.

확인 후 `.env`에서 아래 값을 설정하고 엔진 프로세스를 다시 시작합니다.

```dotenv
RETRIEVAL_KOREAN_LEXICAL=true
RETRIEVAL_LEGAL_BASIS=true
```

결과의 `retrieval_method`에 `korean-bm25`가 있으면 해당 조문이 한국어 검색에서도 회수된 것입니다. 점수는 법적 적합성 확률이 아닙니다. 사용하지 않으려면 첫 값을 `false`로 바꾸고 재시작합니다. 저장된 색인을 삭제할 필요는 없습니다.

다른 개발 환경에는 원본·모델·색인이 자동 전달되지 않습니다. 기존 데이터 준비 절차 후 위 명령을 실행해야 합니다. 법령·판례를 다른 설정으로 재적재했다면 `--check-only`로 확인합니다. 미색인 조각은 E5 검색에는 남지만 BM25 검색에는 참여하지 않습니다.

## 재현

```powershell
python scripts/evaluate_grounded_rag.py --split all --profiles grounded grounded-korean --output data/official/bm25-regression.json
python scripts/evaluate_grounded_rag.py --dataset data/config/retrieval_bm25_validation_v1.json --split test --purpose validation --profiles grounded grounded-korean --output data/official/bm25-validation.json
python scripts/evaluate_semantic_critic.py --korean-bm25 --output data/official/bm25-pipeline.json
```

마지막 명령은 실제 로컬 KG·RAG·LCI, 가상 폐기물 로트, **모의 Azure**로 연결을 점검합니다. 유료 모델·지도 호출이나 실제 GPT의 반박 정확도 평가는 하지 않습니다. 모든 질문을 한정 없이 검증했다는 의미도 아닙니다.

가상 PP 3톤 시나리오에서 새 방식의 법령 검색 결과 3건이 실제 파이프라인에 들어갔습니다. 후보 3개, HTTP 연결 검사 5개와 오류·차단 검사 11개가 통과했습니다. Critic 입력은 88,123자였고, 이번에 확보한 법령 조각 71개는 모두 전송 대상으로 선택됐습니다. **검색·문맥 확장 자체의 누락이나 법령 문서 전체의 완전성을 보장하는 수치는 아닙니다.** 실제 DB를 켠 전체 코드 검사는 892개와 하위 검사 24개가 통과했고 skip은 0개입니다.

## 다음에 채울 부분

- **데이터:** 실제 기업 질문을 익명화하고 관련 조문을 전문가가 검수한 평가셋이 필요합니다. 한 질문에 여러 근거가 필요한 경우도 라벨에 반영해야 합니다.
- **기술:** 배출자 의무의 우회 표현·경매 책임 판례·연간 보고 질문을 놓치는 문제, 검색·원문 확장 전체의 누락 점검, GPU 환경 재정렬 모델 비교가 남았습니다. 현재 결과만으로 자동 적법 판정이나 최종 추천 승인을 내리지 않습니다.

개발 참고: 기존 색인은 필드별 중복 단어를 제거하므로 이 구현의 TF는 원문 반복 횟수 대신 **제목 2·조문 제목/인용 3·본문 1의 필드 출현값**입니다. BM25의 `k1=1.2`, `b=0.75`와 고유 색인어 수 기반 길이 정규화를 사용하며, 엄밀한 BM25F 구현이라고 부르지는 않습니다. IDF·평균 길이는 매 SQL 문에서 현재 공개·요청 코퍼스만 대상으로 계산합니다. 별도 질문 캐시나 외부 전송은 없습니다. [PostgreSQL 텍스트 검색 함수](https://www.postgresql.org/docs/16/functions-textsearch.html)
