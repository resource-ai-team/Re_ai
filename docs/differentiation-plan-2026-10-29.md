# 다음 개발 계획: 근거를 확인하며 경로를 바꾸는 폐자원 검토실

작성일: 2026-10-29. 제안 문서이며 아래 추가 기능이 모두 구현됐다는 뜻은 아닙니다.

## 1. 먼저 바꿔야 할 차별화 설명

**제안하는 제품 설명:**

> 공장에서 발생한 폐자원의 공정 후보를 비교하고, 각 경로의 막히는 조건과 먼저 확인할 자료를 알려주는 AI 검토실.

3D 초원과 아고라는 진입 경험으로 유지한다. 제품의 핵심은 **조건 변경 → 경로·판정 변화 → 근거와 수정 이력 확인**으로 잡는다.
기존 처리 경로는 가정하지 않는다. 공개 시설 사례·명부·문헌의 관계를 실제 허가·이번 로트 수용으로 확정하지 않는다.

공개 소개에서 특정 기능이 보이지 않는다는 이유로 ‘경쟁사에는 없다’고 주장하지 않는다.

**차별화 가설:** 국내 폐자원 한 로트에 대해 공정 연결·시설 조건·법규·비용·탄소를 함께 검토하고, 판정을 바꾸는 조건과 추가 확인 순서를 지도에서 조작·추적하는 경험에 집중한다.
독점성·신규성·구매 의향은 별도 검증이 필요하다.

## 2. 가장 먼저 만들 세 가지

### A. 무엇을 먼저 확인할지 알려주는 기능

현재는 질문을 공정별 작업으로 묶었다. 다음은 **결정에 영향을 주는 순서**로 정렬한다.

1. **경로 검토를 막는 자료:** 폐기물 성상, 시설의 해당 분류 수탁 조건, 필요한 전처리 등.
2. **대안의 우위를 바꿀 수 있는 자료:** 운송·처리 단가, 수율, 산출물 규격·매각 조건, 공정 활동량 등.
3. **결정 이후 보완할 기록:** 현재 판정에 영향을 주지 않는 보고·설명 자료.

질문마다 ‘누구에게 / 무슨 자료를 / 어느 항목으로 / 무엇이 바뀌는가’를 붙인다.
초기 화면은 우선 작업 3개를 제안하되 모든 차단 조건은 확인할 수 있게 하고, 전체 항목은 보존한다.
시험비·소요 시간·관측 확률이 없으면 금전적 정보가치를 계산하지 않는다. 알려진 조건과 범위로 영향 여부만 판별하고, 영향 범위도 모르면 미확인으로 남긴다.

**완료 기준:** 질문을 골랐을 때 관련 후보·공정·근거·예상 변경 항목을 볼 수 있고, 답을 넣으면 그 상태가 다시 평가된다.

### B. 조건을 바꾸면 경로가 달라지는 검토 지도

예: ‘이 로트의 수분이 확인됐다’, ‘수탁 기준서를 받았다’, ‘견적에 운송비가 별도였다’를 입력하면 영향을 받은 경로와 계산을 표시한다.

- 조건은 확인한 문서의 값·규격 또는 명시적으로 표시한 가정에서 가져온다.
- **자료에 근거한 현재 결과**와 **사용자가 가정한 시뮬레이션**을 화면과 저장 공간에서 구분한다. 가정 값을 실제 자료에 덮어쓰지 않는다.
- 선택 경로마다 조건 확인 상태·누락 자료·보류/제외 이유·비용/탄소 범위를 보여준다.
- ‘조건을 충족하면 이 후보를 다시 검토할 수 있다’는 설명과 그 근거를 연결한다.
- 검증된 역전 조건이 없으면 손익분기점·수분 임계값 등을 만들어내지 않는다.

같은 시설의 여러 공정은 **시설 한 건물 안의 공정 단계**로 묶는다. 시설 사이의 도로 이동과 시설 내부의 처리·이동을 다른 연결로 표현한다.
내부 이동을 공개 도로 API로 계산하거나, 그 배출량을 자동으로 0으로 채우지 않는다.
3D 위치는 공정 개념도임을 유지하고 실제 지도·도로거리는 별도로 표시한다.

**완료 기준:** 확인된 조건 하나를 바꿨을 때 판정·영향 구간·수치 변화·이유를 함께 볼 수 있다. 데이터 미확인 표시는 실제 위반·사고 발생과 구분한다.

### C. 반박 이후 무엇이 달라졌는지 보여주는 기능

이미 있는 코드 단위 수정과 선택 Astra Critic을 아래 계약으로 확장한다. 고정된 직렬 파이프라인을 유지한다.

| 지적 종류 | 후속 행동 | 자동으로 확정하면 안 되는 것 |
|---|---|---|
| KG 연결·전처리 누락 | 관련 공정·연결 근거 다시 조회 | 문헌에 없는 공정 연결 |
| 법규·시설 조건 오류 | 해당 조문·예외·수탁 자료 재조회, 근거 대조 | 허가·인수 가능 판정의 임의 변경 |
| 단위·계산·운송 누락 | 확인 근거가 있으면 Python 재계산 | 없는 단가·거리·물량 추정 |
| 탄소 범위 충돌 | 출처·연도·GWP·경계 대조, 비교 보류 | 전력 부분 계수의 공정 전체 적용 |
| 추천 결론 오류 | 검증된 수치와 상태로 재비교 | LLM의 말만으로 최종 순위 변경 |

각 지적은 대상 ID·근거 ID·오류 유형·관련 입력 버전·재확인 단계·미해결 여부를 가진다.
수정된 입력·근거에 영향을 받는 후속 단계만 갱신하고, 영향 없는 시설·견적을 반복 입력하지 않도록 한다.
확인되지 않은 모델 지적은 검토 요청으로 남긴다. 반복 횟수와 호출 예산을 제한하고 미해결 문제는 보류로 종료한다.

아고라에는 내부 추론문 대신 **실제 조회·근거·판정·수정 전후·미해결 항목**을 보여준다.

**완료 기준:** ‘지적 → 재확인 → 근거 있는 수정 또는 보류 → 후속 결과 변화’가 실제 실행 기록으로 이어진다.

## 4. 먼저 확보할 자료

대상 품목은 유지하되 **대표 사례 한 건의 완성도**를 먼저 높인다. 현재 KG에서 확인되는 PET 후보 2개로 시작하고 알루미늄은 다른 소재에서도 작동하는지 보는 후속 사례로 둔다.

- 배출 로트: 실제 성적서·계량표, 성상·수분·오염·물량, 확인한 수거 출입구.
- 후보 시설: 공정·폐기물 분류별 수탁 기준, 허가 근거와 적용 범위, 확인 날짜, 이번 로트의 수용 답변.
- 견적: 전처리·처리·상하차·운송·잔재물·매각의 포함 범위, 단위·유효기간·세금 조건.
- 탄소: 공정별 전력·연료·수율·잔재물 활동량과 비교 가능한 LCI. 공개 전력계수만으로 전체 순위를 만들지 않는다.
- 검수: 어떤 경로가 왜 보류·제외돼야 하는지 담당자가 확인한 정답·근거.

공개 자료는 시설·공정의 조사 근거로 사용한다. 실제 수용·단가·여유 용량을 확인한 것으로 바꾸지 않는다.
현장 자료를 못 받으면 시연용 수치를 가상으로 표시하고 실제 데이터 검증 단계는 미완료로 남긴다.
기업 자료로 축적할 자산은 ‘문서 수’보다 **시설별 조건·근거 버전·오류와 수정 이력**이다. 접근 권한과 사용 허용 범위를 함께 저장해야 한다.

## 5. 다음 10작업일 제안

기간은 제안이며 자료 확보와 팀 일정에 맞춰 조정한다. 각 단계의 완료 기준을 충족한 뒤 다음으로 간다.

| 순서 | 작업 | 산출물·완료 기준 |
|---|---|---|
| 1~2일 | 대표 PET 사례와 확인할 조건·비교 범위 고정 | KG에 있는 2개 경로, 문서 목록, 사실/가정/미확인 표, 판정 기준 |
| 3~5일 | 조건·근거·결과 연결과 우선 확인 작업 구현 | 답을 넣으면 해당 조건과 후속 결과만 갱신, 미확인 자동 통과 금지 |
| 6~8일 | 시설 묶음·조건 변경·변경 전후 UI 연결 | 지도 선택 → 조건/근거 → 답 입력 → 바뀐 경로/계산 재생 |
| 9~10일 | Critic 부분 재실행과 기준선 비교 | 반박 후 수정/보류 재현, 실행 기록·정답·실패 사례·시간/호출량 보고 |

4명 분담 제안:

- **KG 담당:** 시설·공정·연결 유형, 필요한 전처리, 후보별 조건·출처, 실제 사례 확보.
- **RAG 담당:** 법령 적용 대상·예외·현행성·원문 위치, 시설 규격 자료와 검수 기준.
- **엔진/백엔드 담당:** 조건 상태·영향 연결·질문 우선순위·코드 재계산·Critic 재실행·버전 관리.
- **프런트 담당:** 기존 초원 유지, 시설 내부 공정, 조건 패널·가정 모드·변경 비교·실행 기록.

## 6. 차별점을 증명할 평가

같은 GPT 모델·같은 문서·같은 질문을 주는 **일반 RAG 기준선**과 비교한다. 모델을 바꿔 생긴 차이를 우리 구조의 효과라고 설명하지 않는다.

최초 평가 묶음은 개발용 사례와 미사용 평가 사례를 분리한다. 아래 오류를 포함하되 오류 정답은 규칙·확인 문서·현업 검수로 확정한다.

- 실제 수탁 조건과 맞지 않는 시설 연결.
- 필수 전처리 누락, 서로 맞지 않는 인계 규격.
- 운송비·잔재물 처리비 누락, t/kg 혼동, 잘못된 이동 물량.
- 다른 연도·경계·GWP 또는 전력 부분 계수를 혼합한 탄소 비교.
- 문서가 부족한데 실행 가능한 경로로 단정한 경우.
- 조건 하나를 바꾸면 후보의 상태나 경제성 비교가 바뀌어야 하는 경우.

측정할 것은 **잘못된 통과, 원문 일치, 누락 발견, 정당한 보류, 변경 후 계산 일치, 검토 시간, 모델 호출량**이다.
첫 통과 기준은 평가 묶음 내 확정된 필수 제약 위반을 추천 대상으로 승격하지 않는 것, 근거 없는 수치를 채우지 않는 것, 고정된 입력·근거·버전에서 코드 계산이 재현되는 것이다.
유한한 평가셋의 통과를 ‘법적 안전 보장’이나 ‘상용 정확도 100%’라고 부르지 않는다.

실제 Azure 모델·OCR·지도 실호출은 별도 권한·키·호출 예산이 정해진 범위에서 검증한다. 이 계획 작성 중 새 유료 호출·기업 연락·공개 배포는 하지 않았다.

## 7. 대표 시연 장면

1. 가상이라고 표시한 폐PET 로트 입력 → 실제 KG의 후보 2개 표시.
2. 수탁 기준·수분 등 필요한 조건이 없어 관련 경로가 보류 상태로 남음.
3. 성적서에서 이번 로트 값을 선택 → 확인된 조건과 연결된 경로 상태 갱신.
4. 시연용 견적의 빠진 운송/잔재물 항목을 검사에서 발견 → 관련 항목 추가·재계산.
5. 전후 결과를 겹쳐 보고 어느 근거·조건이 차이를 만들었는지 클릭해 확인.
6. 담당자가 검토 결과와 미확인 항목이 담긴 보고서를 받음. 실인수·발주 승인은 별도.

핵심 메시지: **추천 결과와 함께, 그 결과가 성립하는 조건과 바뀌는 이유를 보여준다.**
