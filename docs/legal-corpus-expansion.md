# 법령 RAG 자료 보강

팀원이 만든 RAG 저장·검색 방식을 그대로 사용합니다. 새 벡터 DB나 다른 임베딩 모델을 만들지 않았습니다.

**이 문서의 성능 표는 10월 26일 수집 직후 기록입니다.** 10월 27일에는 상위법 동반 조회·명시 조문 직접 조회·중복 억제를 적용했습니다. 최신 기본 질문 7/7·추가 표현 7/8·동결 검증 8/14와 남은 문제는 [후속 보강 기록](grounded-rag-2026-10-27.md)을 참고하세요.

## 이번에 실제로 넣은 양

2026-10-26 기준 **법령 73개 + 행정규칙 25개 = 98문서, 21,979조각**을 로컬 pgvector에 적재했습니다. 조·항·별표 등 19,238구획이며 별표 728개와 공식 시험기준 PDF 88개·611쪽을 포함합니다. 기존 판례 14개와 기술 요약 12개는 보존했습니다. 현재 전체 검색 코퍼스는 **124문서·22,095조각**입니다.

98개 문서의 저장 여부·384차원·임베딩 규칙·원문 캐시 해시를 실제 DB와 대조했습니다. 현재 버전 중복은 없고, 기본 조문에서 원문이 빠졌던 참조 법령 7개를 모두 확보했습니다. 같은 버전 96개를 재실행했을 때 벡터는 재사용하고 출처 메타데이터만 갱신했습니다.

## 검색 결과도 좋아졌나요?

**자료 확보는 완료했지만 일반 질문의 근거 회수는 일부 낮아졌습니다.** 새로운 고시·지침이 관련 있는 답을 제공해도 기대한 상위법 조문이 Top 5에서 빠지거나, 폐기물 처리 질문에 폐수 처리 조문이 섞이는 문제가 있습니다. 정답 목록을 새 자료에 맞춰 바꿔 점수를 높이지 않았습니다.

| 점검 | 확장 전 | 확장 후 |
| --- | --- | --- |
| 기존 기본 법령 질문 | 6/7 | 5/7 |
| 기존 추가 표현 질문 | 5/8 | 3/8 |
| 별도 검증용 법령 질문, 기존 규칙 정렬 | 10/14 | 6/14 |
| 신규 제목·조문·파일 조회 | 해당 자료 없음 | 15/15 |
| 기존 기본 기술 질문 | 7/7 | 7/7 |
| 별도 검증용 기술 질문 | 9/9 | 9/9 |

모두 개발자 작성·임시 라벨의 **근거 회수 점검**입니다. 법률 전문가의 정답·적용성 평가가 아닙니다. 신규 조회 15/15를 일반 법률 질의 정확도 100%로 해석하면 안 됩니다. [동결한 기존 검증 질문 결과](evaluation/legal-expansion-holdout-2026-10-26.json)

공정별 기본 조문 10개 직접 조회는 유지했습니다. 기본 조문의 명시 참조 중 문서 누락은 7건 → 0건이 됐고, 전체 미해결 참조는 59건 → 51건입니다. 불명확한 법명·위임 규정 등은 계속 확인 필요로 남습니다. [참조 점검](evaluation/legal-context-expanded-2026-10-26.json)

가상 PP 3톤을 실제 KG·RAG·LCI로 처리한 시나리오도 검사했습니다. 후보 3개, HTTP 연결 검사 5개와 비정상 응답/차단 사례 11개가 통과했습니다. Azure는 모의 전송이며 실제 유료 모델 호출은 없습니다. 전체 코드 테스트는 **857개 + 하위 검사 24개, 실패·skip 0개**입니다. [시나리오 기록](evaluation/legal-expansion-pipeline-2026-10-26.json)

**다음 검색 보강:** 폐기물·폐수·대기 등 질문 범위를 구분하고, 상위법 조문과 관련 고시·지침을 함께 회수해야 합니다. 현재 전체 자료를 같은 Top 5 경쟁에 넣는 방식은 개선이 필요합니다. 새 수집 자료를 팀 서버에 넣기 전 이 결과를 함께 검토해야 합니다.

## 어디에 무엇을 저장하나요?

| 항목 | 사용 방식 |
| --- | --- |
| 저장소 | Docker의 PostgreSQL 16 + pgvector, `re-ai-postgres` |
| 문서 / 조각 | 기존 `legal_documents` / `legal_chunks` 테이블 |
| 임베딩 | `intfloat/multilingual-e5-small`, 384차원, 정규화 |
| 임베딩 입력 | 문서는 `passage: 제목 + 구획 제목 + 원문`, 질문은 `query: 질문` |
| 조각 크기 | 기존 LAW 규칙: 최대 1,200자, 겹침 150자 |
| 검색 | 기존 LEGAL 그룹의 벡터·키워드 결합 검색과 규칙 재정렬 |
| 법령과 지침 구분 | 모두 기존 `LAW` 코퍼스에 넣고, 문서 메타데이터의 `legal_source_kind`와 `instrument_type`으로 구분 |

**적재 대상은 이 작업 PC의 DB입니다. 팀 공용 서버 DB에 배포했다고 볼 수 없습니다.** 팀 서버에서는 아래 수집·적재 명령을 실행해야 합니다. 기업 문서와 판례·기술 RAG는 이번 수집 대상에서 제외했습니다.

## 어떤 자료를 모으나요?

[수집 범위 설정](../data/config/legal_scope_expanded.json)에 제목과 사용 목적을 고정했습니다.

- 폐기물관리·순환경제·재활용·건설폐기물·전자제품 자원순환 법령과 하위법령
- 기존 기본 조문에서 참조하는 비료관리법·에너지법·수도법·산업입지법·자동차관리법·해양폐기물법·환경정책기본법과 하위법령
- 조건에 따라 필요한 대기·수질·토양·통합환경허가·국토이용·화학물질·산업안전·위험물 법령
- 운송·수출입·탄소 관련 법령
- 처리업 허가, 배출자 신고, 전자인계, 재활용 용도, 유해특성, 순환자원 인정, 재활용환경성평가, 고형연료제품 관련 고시·지침
- 폐기물공정시험기준의 공식 전문 ZIP: PDF별 페이지 위치를 보존해서 검색

수집 범위에 있다고 모든 사업장에 적용되는 것은 아닙니다. 물질·공정·시설·지역·행위에 맞는 적용성 검토가 필요합니다. 탄소 관련 법령은 LCI 배출계수와 다른 자료입니다.

일반법·고시의 원문을 **RAG에서 찾을 수 있게 만든 작업**입니다. 이를 Neo4j의 법령 그래프로 자동 변환하거나, 업체별 허가 여부를 채우는 작업과는 구분됩니다.

## 수집하면서 막은 오류

1. **시행 예정 개정문 혼입:** 공포 기준 검색 대신 시행일 기준 `eflaw`의 현행 목록을 확인하고, 목록의 MST·시행일로 본문을 고정합니다. 미래 시행 문서는 거부합니다.
2. **비슷한 이름의 법령 선택:** 공백·가운뎃점 표기만 정규화한 정확한 제목을 사용합니다. 하나로 특정되지 않으면 실패 목록에 남깁니다.
3. **행정규칙 첫 조문만 적재:** 반복되는 모든 `조문내용`을 읽고, 별표와 출처를 보존합니다.
4. **장 제목을 제1조로 오인:** `조문여부=전문`인 편·장 제목을 조문에서 제외합니다. 항 없이 직접 나오는 호·목도 보존합니다.
5. **지침 속 ‘법’을 지침 자체로 오인:** 행정규칙의 불명확한 법·영 별칭은 자동 연결하지 않습니다. 명시된 법령명만 따라가고 나머지는 확인 필요로 표시합니다.
6. **안내문을 시험기준 본문으로 오인:** 첨부 안내만 있는 시험기준은 공식 전문 ZIP의 PDF를 읽습니다. 파일명·페이지·SHA-256을 남기며 이미지나 표의 수치를 자동으로 검증했다고 보지 않습니다.

## 다시 수집하고 넣는 방법

프로젝트 루트에서 실행합니다. 로컬 CPU로 임베딩하며 Azure·Solar 호출은 없습니다.

```powershell
pip install -e ".[embeddings,legal-attachments]"
docker compose up -d postgres
resource-rag init-db
python scripts/expand_legal_corpus.py collect
python scripts/expand_legal_corpus.py index
python scripts/verify_legal_expansion.py --output docs/evaluation/legal-expansion-2026-10-26.json
```

기본 수집 기준일은 **2026-10-26**입니다. 다른 날짜로 새로 수집할 때는 `--as-of YYYY-MM-DD --output data/official/새폴더/documents.jsonl`을 두 명령에 동일하게 지정합니다. 현행 API이므로 과거 날짜의 코퍼스를 새로 복원하는 기능은 아닙니다. 원본 캐시와 당시 매니페스트를 보관해야 당시 결과를 재현할 수 있습니다.

첫 임베딩 실행 시 모델 다운로드가 필요할 수 있습니다. 인덱스 적재는 팀과 같은 E5 모델·384차원 설정에서만 진행됩니다. `hash` 테스트 임베딩으로 실제 DB를 채우지 않습니다.

수집 파일은 `data/official/legal-expansion-2026-10-26/`에 보관합니다.

| 파일 | 내용 |
| --- | --- |
| `xml/` | 날짜별 검색 결과와 버전이 고정된 공식 XML 캐시 |
| `attachments/` | 공식 시험기준 ZIP과 PDF 검토 파일 |
| `documents.jsonl` | 기존 EvidenceDocument 형식의 문서 |
| `documents.manifest.json` | 데이터셋 해시·출처·시행일·문서 수 |
| `documents.collection.json` | 수집 성공·실패·별표 누락 기록 |
| `documents.index.json` | 실제 적재 문서·조각 수·내용 해시 |

원본과 모델 파일은 Git에 올리지 않습니다. 범위·코드·출처 목록·검증 결과를 공유합니다. API 인증값도 기록하지 않습니다. 같은 내용·모델·임베딩 규칙이면 재실행 시 건너뛰고, 변경된 문서만 문서 단위 트랜잭션으로 교체합니다. 과거 버전은 비활성 이력으로 보존합니다.

기존 `legal-rag collect` 명령으로 판례를 준비한다면 확장 법령 적재 **전에** 실행하세요. 기존 수집 범위에 포함된 15개 법령이 나중에 들어와 확장 수집 버전을 교체하는 일을 피하기 위한 순서입니다.

## 아직 확인해야 하는 것

- 부칙 전체, 이미지 도표, 모든 별도 첨부와 지방자치단체 조례까지 수집한 상태는 아닙니다.
- 법령 본문을 확보해도 개별 업체의 현행 허가증·이번 로트 인수 여부·처리 용량은 알 수 없습니다.
- PDF 텍스트 추출은 표의 행·열·단위에 대한 육안 검증이나 법률 검토를 대신하지 않습니다.
- 자료 증가와 검색 품질 향상은 별개입니다. 기존 질문과 신규 질문의 결과를 따로 확인합니다.
- 법률 전문가가 적용 조건과 예외를 검토하기 전에는 자동 준법 판정이나 최종 실행 승인에 사용하지 않습니다.
