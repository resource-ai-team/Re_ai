# 가까운 업체와 공정을 확인한 업체를 구분하기

시설 검색 결과에 같은 업체가 여러 공정마다 나타나는 것은 오류라고 단정할 수 없습니다.
한 업체가 여러 공정을 수행할 수도 있고, 넓은 폐기물 분류만 명부에 기재돼 있을 수도 있습니다.
**거리와 공정 수행 근거를 분리해 표시**해야 합니다.

이번에 `/kg/facility-candidates`와 `/analysis/site-discovery`에 사업장 식별 근거를 연결했습니다.

## 결과에서 볼 것

명부 후보의 `research_packet.evidence_links`는 다음을 반환합니다.

| 필드 | 의미 |
| --- | --- |
| `identity_status=not_linked` | 공개 공정 자료의 사업장과 같은 명부 행인지 검수하지 못함 |
| `identity_status=reviewed_same_site` | 공식 사업장 자료와 특정 명부 스냅샷의 업체·주소를 대조해 검수 연결 |
| `facility_key` | 명부 행과 대조한 KG 사업장 ID. 명부 ID와 별도 |
| `stage_capability=published_site_process` | **이번 요청 공정**에 대해 사업장 단위 공개 수행 근거가 있음. 현재 운영 승인은 아님 |
| `stage_capability=site_role_hypothesis` | 기업의 사업·사업장 역할로 만든 가설. 직접 수행 근거 미확인 |
| `stage_capability=not_established` | 이번 공정의 수행 근거를 연결하지 못함. 불가능하다고 판정한 것도 아님 |
| `capability_keys`, `source_evidence` | 이번 사업장·요청 공정에 해당하는 연결과 URL·위치·확인일·자료일 |
| `identity_link` | 검수한 명부 ID·원본/행 SHA-256·식별 출처·검수일 |

**같은 사업장 확인 ≠ 해당 공정 확인 ≠ 현재 허가·로트 인수 확인**입니다.
현행 허가·인수·여유 용량은 여전히 `null`이고 `dispatch_approved=false`입니다.

사업장 조사 응답의 `facility_searches[].evidence_coverage`에서는 수집한 명부 후보 수와
그중 동일 사업장 연결·공정 공개 근거·역할 가설 건수를 따로 볼 수 있습니다.
원래 KG 참조 시설의 직접 근거/가설 건수도 별도입니다. **받은 페이지 범위의 집계**이며
전체 명부의 검증률·국내 시장의 공정 수행 비율이 아닙니다.

## 어떤 자료를 추가했나

- **알엠 화성공장:** [COSMO의 PET 컵 사업자 공고](https://www.cosmo.or.kr/boardDownload.es?bid=0001&list_no=50188&mid=a10401000000&seq=1)와
  [한국환경공단의 2025-07-09 공고](https://portal.budamgum.or.kr/cmb/portal/board.do?boardId=9384&menuId=11&search_sys=EPR&tp=N)의
  사업자·주소를 명부 한 행에 대조했습니다. 공식 도로명 주소의 시·면·도로·건물번호를 비교했고,
  명부의 추가 행정구역 표기 `만세구`는 검수 과정에서 구분했습니다. 다른 건물번호나 오산 사업장은 합치지 않았습니다.
  **PET 컵 사례를 PET병 세척·압출 근거로 확대하지 않아 신규 capability는 0개**입니다.
- **삼양 시화공장:** [공식 사업장 안내](https://www.samyangpackaging.com/kr/company/about)로
  기존 지역 수준 정보에 도로명주소·법인 명칭 근거를 보강했습니다. 해당 공장을 명부의 동명 업체에 자동 연결하지 않았습니다.
- **BGF:** 예산·화성 등 사업장 역할은 재확인했지만 개별 소재별 세척·압출 직접 근거가 부족해 기존 가설을 유지했습니다.

[조사 자료와 미확인 사항](facility-primary-research-2026-10-24.md)에 원본 해시와 위치를 기록했습니다.
Git에는 팀이 작성한 사실 요약·공식 주소·해시와 명부 ID만 넣습니다. 명부의 원시 업체명·주소·전화번호,
기업 홈페이지 전체·PDF 원문은 로컬에 남기며 외부 모델에는 전송하지 않습니다.

## 잘못된 연결을 막는 방식

1. 명부 ID는 파일 해시·행번호에 묶인 **스냅샷 ID**입니다. 사업장 영속 ID로 쓰지 않습니다.
2. `Facility.registry_identity_links`에 검수한 행 ID·원본/행 해시·식별 출처·확인일을 저장합니다.
   시설 주소와 같은 시설에 연결된 출처가 필요합니다. 같은 행을 두 시설에 연결하면 적재를 거절합니다.
3. 실행 시 활성 Neo4j의 참조·명부를 읽습니다. 새 스냅샷에 옛 이름 연결을 자동 이식하지 않습니다.
   같은 행 ID인데 해시가 다르거나 연결이 모호하면 무결성 오류로 거절합니다.
4. 이번 `transition_key`의 capability만 조회합니다. 파쇄 근거를 세척·압출로 확장하지 않습니다.
5. 기존 외부 모델 보기에서는 명부 본문과 이 식별 패킷을 계속 가립니다.

새 근거를 반영한 개발 환경에서는 다음 순서로 검증·재적재합니다.

```bash
resource-kg validate
resource-kg import --rebuild
resource-kg audit
```

새 KG 세대를 활성화하기 전에 감사하며, 이전 세대와 별도 명부는 보존합니다.
오래된 실행 결과·커서는 새 세대에서 그대로 재사용하지 않습니다.

## 실제 실행 확인

새 자료를 실제 Neo4j에 재적재했습니다. 공정 참조는 출처 12개·시설 8개·공정 연결 18개이며,
W2RKG 문헌과 전국 명부 9,604개 등록 레코드는 별도 범위로 유지했습니다.

[실제 API 기록](evaluation/facility-identity-2026-10-24.json)에서 알엠 명부 행을 PET 세척·PP 세척
요청으로 각각 조회했습니다. 두 번 모두 `reviewed_same_site`이지만 공정은 `not_established`였습니다.
공공기관의 PET 컵 사례를 다른 형태·소재의 세척 능력으로 확대하지 않은 결과입니다.

전체 PostgreSQL·Neo4j 검사 **636개·24 subtest 통과, 1개 skip**을 확인했습니다.
skip은 로컬에 없는 사용 조건 제한 LCI 원본 검사입니다. 새 실제 Neo4j 식별 검사 4개는 가상 업체·자료로
긍정 연결·다른 공정으로 확대 방지·외부 모델 본문 차단·새 명부 연결 재사용 방지를 검사합니다.
이를 실제 업체의 처리 정확도 정답셋으로 해석하지 않습니다. 생성 모델은 호출하지 않았습니다.

명부를 적재한 팀원은 다음 명령으로 같은 검사를 재현할 수 있습니다.

```bash
python scripts/evaluate_facility_identity.py --output facility-identity-result.json
```

로컬에 다른 명부 버전이 있으면 검수된 행이 해당 스냅샷에 없다는 상태를 기록하며 이름으로 재연결하지 않습니다.

## 아직 필요한 것

실제 수행 공정·투입 규격·지정폐기물 해당 여부·현재 허가·이번 일정의 수용 조건은 계속 필요합니다.
부족한 공정 근거를 모델의 추론으로 채우거나, 거리순 목록을 적합성 순위로 바꾸지는 않습니다.
다음 수집은 공장별 설비/공정 설명서와 공식 허가 자료를 우선하며 실제 견적·도로 경로 연결은 후속입니다.
